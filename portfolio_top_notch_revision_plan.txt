1. DESIGN PRINCIPLES (non-negotiable, apply to every phase)
--------------------------------------------------------------------------------
P1. JUICE OVER JANK. Every interaction gets: anticipation (wind-up) -> impact
    (hit-stop/flash) -> follow-through (particles/settle). The game already
    does this partially (hitStop, shakeTimer, squash-and-stretch exist) —
    extend the pattern, don't replace it.

P2. TWO RENDERING ARCHITECTURES, ONE CONTENT PIPELINE. This codebase has a
    hand-rolled 2D canvas engine (Engine.js/Renderer.js) AND several
    react-three-fiber scenes (GlobeGallery, MagicalPortal, SkillTree,
    Holocron). "Playable for both architectures" means: the SAME piece of
    content (a project, a cert, an achievement) can be triggered from a 2D
    hop AND from a 3D node-click, runs the SAME minigame, and lands on the
    SAME reveal card. Right now GlobeGallery and Holocron bypass minigames
    entirely and just pop a flat image/card — that inconsistency is the
    single biggest architectural gap to close (Phase 5).

P3. NEVER BLOCK THE RECRUITER. The existing "RECRUITER SKIP" button and
    per-minigame ESC/auto-skip timers are a deliberately smart feature for a
    placement portfolio — a hiring manager must never be forced through a
    minigame. Every new minigame keeps: ESC-to-skip, a hard auto-skip timeout
    (~4-6s), and full function under prefers-reduced-motion. This is a hard
    requirement, not a nice-to-have.

P4. PERFORMANCE IS A FEATURE. Adding 3D everywhere on top of an already-busy
    2D canvas loop can tank frame rate on the exact mid-range Android phones
    a recruiter might use. Every new visual effect is gated behind a
    graphics-tier check (Phase 0). Ship adaptive quality, not a demo that
    only runs on your M1 Air.

P5. USE WHAT'S ALREADY PAID FOR. @react-three/postprocessing is a listed
    dependency and is currently imported NOWHERE in src/. That's a free
    bloom/vignette upgrade sitting unused. Similarly, groq-sdk is a listed
    dependency with zero imports anywhere and no API routes exist — see
    Appendix C for a stretch idea that finally uses it.

P6. CONTENT STAYS TRUTHFUL. All copy, stats, and links in gameContent.js are
    real achievements — no new phase should invent fake data. Where new
    fields are needed (rarity, matchIcons, codeSnippet) they're derived from
    existing fields wherever possible (see Phase 1.3's auto-rarity mapper).

  - A full custom audio-synth SFX layer (layered oscillators, no sample

    replicate for new effects.
  - A real preloader with progress bar, not a spinner.
  - Recruiter Skip + per-zone minimap + best-time persistence.
  - Three separate r3f 3D scenes already exist (GlobeGallery finale,
    MagicalPortal card backdrop, SkillTree 3D tech tree) — the 3D
    infrastructure is there, it's just disconnected from the main loop.

WHAT'S HOLDING IT BACK (the actual gaps this plan closes):
  - THE REVEAL MOMENT IS FLAT. Hitting a `?` block calls `proceedToCard()`
    which sets `activeCard` -> renders `.content-card`, a static bordered
    div (PortfolioGame.jsx line ~771). No 3D, no physical "opening"
    feeling — the literal thing you asked to fix.
  - proceedToCard's setup logic (open card + trigger the canvas "takeover"
    background zoom) is COPY-PASTED FOUR TIMES: in handleCanvasClick
    (~L238-246), the Enter-key handler (~L344-356 and ~L360-371), and the
    block/portal/photo collision handler (~L472-476). One bug fix has to be
    made in four places today.
  - Certs have no minigame at all. `getMinigameCategory()` returns null for
    every cert_* key — they're either a passive `hover` proximity reveal
    (7 of them) or the single `cert_holo` portal into Holocron, which itself
    just swaps a flat `<img>` on click. This is exactly the "no fun hop, no
    play" you described.
  - HOLOCRON AND GAMECONTENT.JS HAVE TWO DIVERGED CERT DATABASES.
    Holocron.jsx hardcodes its own `CERTS` array pointing at
    /public/files/*.png (the real, full-resolution cert scans, verified
    3308x2520 to 7090x5080px, 780KB-4MB each). Meanwhile
    gameContent.js's BLOCK_CONTENT.cert_* entries have the richer
    badge/desc/narration copy but point at generic /preview-N.webp photos
    instead of the actual certificates. Two sources of truth, out of sync.
  - /public/certs/ IS DEAD. Confirmed unreferenced anywhere in src/, and 3 of
    its 7 files (ps_cert.png, python_cert.png, sql_cert.png) are byte-for-
    byte identical placeholder stubs (same MD5 hash, 800x450 WebP). Clean up
    or repurpose in Phase 5/0.
  - THE 3D SCENES SKIP MINIGAMES ENTIRELY. GlobeGallery's node click and
    Holocron's cert click both go straight to a reveal, bypassing the
    quiz/decrypt/rhythm layer the 2D run uses for the same content. This is
    the direct cause of the "two disconnected architectures" feeling.
  - NO DEVICE-PIXEL-RATIO HANDLING. Confirmed: `canvas.width = W` uses raw
    window.innerWidth with zero devicePixelRatio scaling anywhere in the
    codebase. On any Retina/high-DPI screen (including your own M1 Air, and
    most phones sold since 2018) the game canvas renders visibly softer than
    the crisp DOM UI sitting on top of it. This is a ~20-line fix with an
    outsized effect on "does this look premium." Do it first — see Phase 4.1.
  - @react-three/postprocessing installed, zero imports. Free bloom sitting
    on the table.
  - Zone differentiation is a color palette swap, not a biome. `ZONES` in
    gameContent.js differ only by 6 hex values; `drawBackgroundElements`
    only branches on 3 buckets (AGRICULTURE / *MEMORIES* / everything else)
    — PROJECTS, SKILLS, HACKATHONS, CERTS, CONTACT all render the same
    generic "tech skyline."
  - Minigames are 3 flavors (quiz/decrypt/rhythm) reused across
    thematically unrelated content, and none of them exist in a 3D-native
    form for when they're triggered from inside an already-3D scene.

0.4 Create the graphics-tier detector:

    // src/lib/detectGraphicsTier.js
    export function detectGraphicsTier() {
      if (typeof window === "undefined") return "medium";
      if (window.matchMedia("(prefers-reduced-motion: reduce)").matches) return "low";

      const mem = navigator.deviceMemory || 4;        // GB, Chrome-only; 4 = safe default
      const cores = navigator.hardwareConcurrency || 4;
      const isMobile = /Android|iPhone|iPad/i.test(navigator.userAgent);

      if (mem <= 2 || cores <= 4) return "low";
      if (isMobile || mem <= 4) return "medium";
      return "high";
    }

    Tier meanings used throughout the rest of this plan:
      low    -> no postprocessing, capped particle counts, DPR capped at 1,
                CrateReveal uses CSS only (skip CrystalShatterReveal's r3f
                variant, fall back to the CSS crate even for legendary items)
      medium -> postprocessing on for 3D set-pieces only (Holocron/SkillTree/
                Globe), DPR capped at 1.5, full particle counts
      high   -> everything on, DPR capped at 2

1.1 Shared state store. Right now progress/settings live in ~15 separate
    useState hooks inside PortfolioGame.jsx and localStorage is read/written
    ad hoc (bestTime only). The 3D scenes (GlobeGallery, Holocron, SkillTree)

    // src/state/gameStore.js
    "use client";
    import { create } from "zustand";
    import { persist } from "zustand/middleware";

    export const useGameStore = create(
      persist(
        (set, get) => ({
          // ---- persisted progress ----
          unlockedKeys: [],          // contentKeys opened at least once
          bestTime: null,
          musicOn: true,
          sfxOn: true,
          graphicsTier: "auto",      // "auto" | "high" | "medium" | "low"

          // ---- transient session (not persisted) ----
          score: 0,
          coins: 0,
          activeContentKey: null,    // key currently mid-reveal
          revealStage: "idle",       // idle | impact | crate | card
          revealAnchor: null,        // {x, y, accent} screen coords, or null (3D-sourced)
          revealSourceType: "2d",    // "2d" | "3d"
          minigame: null,            // { category, contentKey, sourceType }

          unlock: (key) => set((s) =>
            s.unlockedKeys.includes(key) ? s : { unlockedKeys: [...s.unlockedKeys, key] }),
          addScore: (n) => set((s) => ({ score: s.score + n })),
          addCoins: (n) => set((s) => ({ coins: s.coins + n })),

          startReveal: (key, anchor, sourceType = "2d") =>
            set({ activeContentKey: key, revealAnchor: anchor, revealSourceType: sourceType, revealStage: "impact" }),
          setRevealStage: (stage) => set({ revealStage: stage }),
          endReveal: () => set({ activeContentKey: null, revealStage: "idle", revealAnchor: null }),

          startMinigame: (category, contentKey, sourceType) =>
            set({ minigame: { category, contentKey, sourceType } }),
          endMinigame: () => set({ minigame: null }),
        }),
        {
          name: "portfolio-progress",
          partialize: (s) => ({
            unlockedKeys: s.unlockedKeys, bestTime: s.bestTime,
            musicOn: s.musicOn, sfxOn: s.sfxOn, graphicsTier: s.graphicsTier,
          }),
        }
      )
    );

1.2 UNIFY THE FOUR DUPLICATED TRIGGER BLOCKS into one function. Today,
    "open a piece of content" is implemented four separate times inside
    PortfolioGame.jsx (handleCanvasClick, the block-hit collision handler,
    the Enter-key proximity handler, and the portal/photo overlap handler),
    each manually setting up `takeover`/`proceedToCard`. Replace all four

    function triggerContent(b, content, sourceType = "2d") {
      const category = getMinigameCategory(b.contentKey);
      const anchor = b.screenX != null
        ? { x: b.screenX + b.w / 2, y: b.screenY, accent: getZone(b.x).accent }
        : null; // null = 3D-sourced trigger, reveal anchors to screen-center instead

      useGameStore.getState().startReveal(b.contentKey, anchor, sourceType);
      if (content.vehicle) setVehicles(v => [...v, { emoji: content.vehicle, y: Math.random()*200+100, t: Date.now() }]);

      if (category) {
        useGameStore.getState().startMinigame(category, b.contentKey, sourceType);
      } else {
        useGameStore.getState().setRevealStage("crate"); // straight to Phase 2's reveal
      }
    }

DESIGN CHOICE, STATED UP FRONT: don't spin up a full three.js <Canvas> for
every single one of the ~40 "block"-type reveals — that's 40 potential WebGL
contexts fighting the already-busy 2D game canvas, which will hurt frame
rate especially on mobile. Instead:
  - Common reveals (block/hover/photo types, ~50 entries) get a CHEAP,
    GPU-accelerated CSS-3D crate (real perspective/rotateX/rotateY, no
    WebGL). Feels fully 3D to the player, costs almost nothing.
  - High-value reveals (revealStyle: "crystal" — capstone projects, 1st-
    place wins, cert_holo) get the full r3f CrystalShatterReveal treatment,
    reusing the icosahedron/particle code that already exists in
    MagicalPortal.jsx instead of writing new three.js boilerplate.
This is a deliberate performance/spectacle tradeoff: save the heaviest
effect for the moments that matter most.

2.2 useCardTilt — pointer-tilt for the holographic card:

    // src/hooks/useCardTilt.js
    import { useRef, useCallback, useState } from "react";

    export function useCardTilt({ max = 14, scale = 1.03 } = {}) {
      const ref = useRef(null);
      const [style, setStyle] = useState({});

      const onMouseMove = useCallback((e) => {
        const el = ref.current; if (!el) return;
        const rect = el.getBoundingClientRect();
        const px = (e.clientX - rect.left) / rect.width;
        const py = (e.clientY - rect.top) / rect.height;
        const rotateY = (px - 0.5) * max * 2;
        const rotateX = (0.5 - py) * max * 2;
        setStyle({
          transform: `perspective(900px) rotateX(${rotateX}deg) rotateY(${rotateY}deg) scale(${scale})`,
          "--sheen-x": `${px * 100}%`, "--sheen-y": `${py * 100}%`,
        });
      }, [max, scale]);

      const onMouseLeave = useCallback(() => {
        setStyle({ transform: "perspective(900px) rotateX(0) rotateY(0) scale(1)", "--sheen-x": "50%", "--sheen-y": "50%" });
      }, []);

      return { ref, style, onMouseMove, onMouseLeave };
    }

    On touch devices, skip the tilt (no hover) and just keep the static
    entrance animation — check `'ontouchstart' in window` and short-circuit.

    // src/components/game/reveal/CrateReveal.jsx
    "use client";
    import { useEffect, useState } from "react";
    const FACES = ["front", "back", "right", "left", "top", "bottom"];

    export default function CrateReveal({ accent = "#00ffff", anchor, onDone, reducedMotion }) {
      const [cracking, setCracking] = useState(false);

      useEffect(() => {
        if (reducedMotion) { onDone?.(); return; } // skip straight to card
        const t1 = setTimeout(() => setCracking(true), 620);
        const t2 = setTimeout(() => onDone?.(), 1080);
        return () => { clearTimeout(t1); clearTimeout(t2); };
      }, [onDone, reducedMotion]);

      const stageStyle = anchor
        ? { justifyContent: "flex-start", alignItems: "flex-start" }
        : {};
      const boxStyle = anchor
        ? { position: "absolute", left: anchor.x - 42, top: anchor.y - 42 }
        : {};

      return (
        <div className="crate-reveal-stage" style={stageStyle}>
          <div className={`crate ${cracking ? "cracking" : ""}`}
               style={{ "--zone-accent": accent, ...boxStyle }}>
            {FACES.map(f => (
              <div key={f} className={`crate-face ${f}`}>{f === "front" ? "?" : ""}</div>
            ))}
          </div>
        </div>
      );
    }

3.1 PATTERN, FULLY WORKED EXAMPLE — CIRCUIT SPLICE
    (replaces DecryptPuzzle for hardware/security-flavored entries:
    avangard, kavach, prashasan)

    Mechanic: N output pins (left) must be dragged to their matching input
    pin (right, pre-shuffled) before a countdown. Correct connection = spark
    particle + tone; full match = solved.

    Logic hook (shared by both views):

    // src/components/minigames/circuitSplice/useCircuitPuzzle.js
    import { useState, useCallback, useMemo } from "react";

    export function useCircuitPuzzle(content, { pinCount = 4 } = {}) {
      const pins = useMemo(() => {
        const labels = (content.matchIcons?.length ? content.matchIcons
          : ["A", "B", "C", "D"]).slice(0, pinCount);
        return { outputs: labels, inputs: [...labels].sort(() => Math.random() - 0.5) };
      }, [content, pinCount]);

      const [connections, setConnections] = useState({});   // outputId -> inputId
      const connect = useCallback((outputId, inputId) =>
        setConnections(c => ({ ...c, [outputId]: inputId })), []);

      const solved = pins.outputs.length > 0 &&
        pins.outputs.every(o => connections[o] === o);

      return { pins, connections, connect, solved };
    }

    2D view: SVG overlay, output pins as circles on the left edge, input
    pins on the right edge, drag draws a live line (pointer events via
    @use-gesture/react's useDrag), drop-on-target calls connect(). On
    solved, fire a spark burst (reuse spawnCircuitBurst pattern from
    AuraSystem.js) then onComplete(bonus).

    3D view (CircuitSplice3D.jsx, mounted only when triggered from inside
    Holocron/SkillTree): same hook, pins rendered as small emissive
    <sphereGeometry> nodes positioned in a ring via the same Fibonacci-
    lattice math GlobeGallery.jsx already uses, connections drawn with
    drei's <Line>, dragging done via useThree's raycaster on pointer move.

    THIS HOOK+2D-VIEW+3D-VIEW SPLIT IS THE TEMPLATE — replicate it for any
    future minigame; don't build monolithic components again.

3.2 MEMORY LATTICE (new — this is the direct answer to "hops to open
    boxes to view certs" — becomes the primary CERTS-zone interaction)

APPENDIX C — OPTIONAL STRETCH IDEAS (not required, worth knowing about)
================================================================================
C1. groq-sdk is a listed dependency with zero imports anywhere and no API
    routes exist in this project. The game already has an AI-guide
    character (ARGUS, the 🤖 in the guide bubble) speaking scripted lines
    from the GUIDE array. A genuinely differentiating stretch feature:
    add a minimal Next.js API route that lets a recruiter type a question
    to ARGUS ("what's his strongest project?") and get a live Groq-backed
    answer grounded in gameContent.js's real data via a system prompt —
    turning the existing guide character from scripted into actually
    interactive. This would need its own scoped plan (rate limiting,
    prompt grounding, a small chat UI) — flagging it here because the
    dependency is already sitting there unused, suggesting it may have
    been the original intent.

C2. The minimap (.minimap-container) currently only shows zone markers and
    player position. Once Phase 1's unlockedKeys tracking exists, add
    small dots for unlocked-vs-locked content per zone on the minimap —
    gives a real sense of completion progress at a glance.

C3. Once Phase 5's parity pass is done, consider a "New Game+" toggle:
    second playthrough starts with all zones unlocked and jumps straight
    to Recruiter-Skip-style zone select, for a returning visitor who
    doesn't want to replay the full platformer run.
